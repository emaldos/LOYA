# Subsystems
How the main parts of LOYA NG work inside, and the rules each one depends on. Start with [ARCHITECTURE.md](ARCHITECTURE.md) for the overall layout.
## Storage
The as built storage spec is [`Cores/storage_migration_plan.md`](../Cores/storage_migration_plan.md). The short version:
- **`Cores/common_db.py`** owns `Data/` (created 0700), the main database `Data/Note_LOYA_V1.db`, the lock flag and the session key. `connect()` raises `DatabaseLocked` instead of ever creating an empty plain database where an encrypted one belongs.
- **Schema migrations** are numbered and additive (`DB_SCHEMA_VERSION=18`), keyed on `PRAGMA user_version`, with each step recorded in `SchemaMigrations`. Never edit an old step; add a new one.
- **`Cores/db_driver.py`** is the only place that opens SQLite. It uses `sqlcipher3` when available, `sqlite3` otherwise, one driver per process. Use `db_driver.Error` and `db_driver.Row`, never the `sqlite3` classes. The CVE index is the one deliberate exception: public data in its own plain SQLite file.
- **`Cores/crypto_store.py`** is the key model. A random 256 bit data key is wrapped with AES-256-GCM under a key derived from the PIN with Argon2id (scrypt as a fallback that is upgraded later). Changing the PIN rewraps the key without touching the data. Purpose keys for the database and for files come from HKDF. Encrypted files use the `LOYAENC` format with chunked GCM, so reordering, truncation and appended data are detected. `atomic_write()` is the safe way to write any file.
- **`Cores/doc_store.py`** stores the small JSON files as plain files, or as `AppDocs` rows when encryption is on. While locked, reads return defaults and writes fail; it never falls back to plaintext.
- **`Cores/secret_store.py`** keeps API keys in the OS keyring, else the encrypted `Secrets` table, else memory for the session.
- **`Cores/storage_migration.py`** turns encryption on or off as a journalled migration (`Data/storage_migration.json`) with a backup first. Originals stay untouched until the commit step, and `recover()` finishes or rolls back an interrupted run at startup.
- **`Cores/loyabak.py`** is the encrypted backup format. It embeds the key file from backup time, so a backup restores anywhere with the PIN that was current then, or with the backup password when encryption at rest is off. Every full backup and every password-protected work export (`.loyawork`) uses it.
- **`Cores/Services/work_export.py`** and **`work_import.py`** are Export my work and its import: an allowlist of content (the `CLASSIFICATION` constant), a fresh content-only SQLite file, a manifest, and a preview then merge or replace on import. Secrets and machine state are never exported, and are ignored in old full-data zips.
- **`Cores/target_profiles.py`** handles target profiles. The default profile uses `Data/Targets.json` and `Data/target_values.json`; other profiles live under `Data/Profiles/<id>/`.
## Security
- **PIN and lock** (`Cores/Services/security_service.py`). Minimum PIN length is 4, or 6 with encryption at rest. After 3 wrong attempts the wait doubles from 30 seconds up to an hour. `unlock()` proves the key opens the database before using it. `lock_now()` locks the bridge, pauses the MCP server, stops agents and chain runs, checkpoints the database and wipes the key.
- **Bridge lock guard.** See [ARCHITECTURE.md](ARCHITECTURE.md#the-bridge). Several services check the lock again on their own (CVE, WSL, chains, attachments, MCP, and the MCP HTTP server, which answers 423).
- **Data folder permissions.** `harden_data_permissions()` runs at every start. POSIX: folders 0700, files 0600. Windows: a folder that still inherits its ACL gets inheritance removed and full control for the current user, SYSTEM and Administrators in one `icacls` call on the folder only, so the files inherit the new ACL. Folders that are already hardened only get `/reset` on children that cannot be read. Failures only log, so the user is never locked out.
- **Audit log.** `log_audit_event` is the single redaction point. Lock, unlock, PIN and encryption events go to `Data/security_audit.jsonl`; with encryption on, the rest goes to the encrypted `AuditEvents` table. A restore merges the log and never rolls it back.
- **The security audit** is [SECURITY-AUDIT.md](SECURITY-AUDIT.md). Findings are `SA-01` to `SA-39` and hand offs `H-01` to `H-10`. The Test column names the regression test; in `tests/test_security_audit.py` classes are per finding, and in `tests/js/security_audit.js` each check starts with its ID.
## Updater
- The only update source is `OFFICIAL_SOURCE_REPO` in `Cores/Update/update_helpers.py`, duplicated in `apply_update.py`; the two must match. Forks and look alike repositories are refused.
- `update_service.py` reads the latest stable release. The package must be the release asset `LOYA-NG-vX.Y.Z.zip`, its SHA-256 must match every published source (GitHub's asset digest, a `SHA256SUMS` asset, a `SHA256:` line in the notes), it must unpack safely and its `CurrentVersion.info` must equal the release version.
- Before applying, a data backup and a code snapshot (`Cores/Update/OldVersions/`, last 2 kept) are written. `apply_update.py` runs as a separate process with `python -I` after the app closes, hashes and extracts the same private copy, replaces only the app folders and files, and restarts.
- The new version must call `update.launch_ready` within 180 seconds. If it does not, the snapshot is restored and the old version restarts. Data is never touched by a rollback.
- `recovery.py` and `downgrade.py` are the console behind `RunNote.py --recovery`. `backup_restore.py` writes and restores backups with size and entry limits, and never mixes plain and encrypted backups.
## Terminal
- **`Cores/Services/terminal_service.py`** runs sessions. Windows uses ConPTY (`conpty.py`) when enabled or for full terminal and task sessions, with a liveness probe and a pipe fallback. POSIX uses a pty, resizes with `TIOCSWINSZ` and kills the whole process group.
- **Full terminal mode** (`UI/js/components/terminal-emu.js`) uses the vendored xterm.js with the DOM renderer only (WebGL is not vendored because of WebKitGTK problems). Keys go raw to the shell; LOYA keeps only Ctrl+Shift+C, V and F. CLI tabs for Claude Code and Codex always use it.
- **Jobs.** Commands run as jobs in the `TerminalJobs` table, found in the shell output by markers like `__LOYA_JOB__<key>|<exit>|<cwd>__END__`. Batches run up to 16 jobs at once (4 by default). Output above 512 KB spills to `Data/job_output/`, encrypted when encryption is on. AI requested commands go through an approval queue.
- **Saved sessions** live in `Data/terminal_sessions.json` through `doc_store`. Scrollback is stripped of ANSI codes and passed through `redact_secrets`, which masks passwords, hashes, tokens, keys and credentials in URLs.
- **Elevation** uses a UAC helper with a localhost socket and token handshake on Windows, and `sudo` on Linux.
- **`wsl_kali_service.py`** (Windows only) is the Kali on WSL setup wizard. It merges only its own keys into `.wslconfig` after a backup, and runs every command as an argv list.
## Chains
- **Linear chains** are playbooks (`playbooks_service.py`) run by `terminal_service.start_chain` with stop or continue policies. Callers (the `/name` used to run a chain from the terminal) follow `Cores/chain_callers.py`.
- **Chain diagrams.** `flow_service.py` is the facade, `flow_store.py` the storage, `flow_schema.py` the validation and `flow_engine.py` the runner. Each `FlowRun` runs on its own thread with caps: 50 visits per node, 3 levels of sub chains, 8 active runs. Commands go through the terminal job system, and every run stops when the app locks.
- **`flow_rules.py`** never uses `eval` or `exec`. Expensive regular expressions run in a helper process that can be killed, and each shell has its own quoting function.
- **`flow_nodes.py`** holds the node catalog and handlers. After changing it, regenerate `UI/js/components/flow-catalog.js` with `tools/gen_flow_catalog.py`.
- **Script isolation** (`flow_scripts.py`). A script runs from an argv list in a throwaway folder with a minimal environment, an output cap, a timeout and a tree kill. On Linux it runs under bubblewrap with a read only root, `Data/`, `Logs/`, `Backups/` and home secrets hidden, and no network unless the node allows it. AI made or unreviewed diagrams can never run unsandboxed.
- **Run History** (`chain_history.py`) exports and imports `loya-chain-bundle` files. Imported chains arrive unreviewed.
## AI
- **`ai_service.py`** holds AI settings, providers (hosted API, Ollama, LM Studio, MCP) and AI Roles. Each permission maps to tools; delete and shell permissions default to deny and sensitive ones are always denied. `authorize()` is the single gate for every tool call, from any client, and Ask permissions wait for the user's approval.
- **`ai_chat_service.py`** is the in app chat. It builds the MCP server in process and calls tools through it, so chat uses the same permission gate as external clients. A reply can use at most 5 tool rounds.
- **MCP server.** `Cores/Bridge/mcp_server.py` registers the core tools and loads `mcp_app_tools.py`, `mcp_chain_history_tools.py` and `mcp_flow_tools.py`. `Cores/Services/mcp_local_service.py` serves it on `127.0.0.1:8765` (or a free port) with a bearer token per start, per client tokens and Host and Origin checks. `mcp_cli_bridge.py` is a standard library stdio to HTTP bridge for the user's own CLI. Every tool and its permission is listed in [MCP-COVERAGE.md](MCP-COVERAGE.md).
- **External agents.** `ext_agents_service.py` runs the Claude Agent SDK (through `ext_agent_claude_runner.py`) or `codex exec` inside an isolated workspace in `Data/external_agents/`, with its own MCP token, an allow listed environment, file tools confined to the workspace and results redacted. `ext_connections_service.py` connects the user's own Claude Code or Codex CLI to the MCP server. `ext_cli_launch.py` only types the bare CLI name into a terminal tab.
- **Bundled skills** in `AI Template/skills/` are installed into agent workspaces and connected CLIs. Each copy records its version and hash, so untouched copies are updated and edited ones are kept.
- **Elements.** Elements are the target placeholder keys, written `{Name}` in commands and filled from the live target's values. `targets_service.auto_add_target_values()` registers every new `{Key}` found in saved notes and commands. `Cores/Services/ai_element_rules.py` holds the one rule every AI is given (write changeable values as elements, reuse an existing element by meaning, else a clean new name such as `{IPv4}` or `{Ports}`), the alias table it matches meanings with, and the literal value detector whose findings come back from the note and command MCP tools.
## Reporting
- `reports_service.py` is the model: reports, sections, findings and versions, all in the database, with assets stored as blobs.
- `report_export.py` builds one render model and dispatches to HTML, Markdown, CSV, SARIF, XLSX, PDF and DOCX writers, all through `atomic_write`.
- `report_export_html.py` produces a single script free HTML file with data URIs that serves the preview, the HTML export and the PDF.
- PDFs are printed by the web engine (`report_pdf_native.py`, scripts off) with fpdf2 (`report_export_pdf.py`) as the fallback.
- `report_xlsx.py` never writes formulas. `report_import.py` treats imported files as untrusted and sanitises them. `report_ai.py` shows a preview and asks for consent before sending anything.
## CVE Intel
- `cve_service.py` is the single network choke point: opt in, offline mode and the lock are checked, only fixed HTTPS hosts are allowed, requests are throttled per source and text is sanitised.
- `cve_index.py` keeps the offline index in `Data/cve_index/cve_index.sqlite` with an FTS5 table, unpacked from `Assets/cve/cve-index.sqlite.xz` with a size limit and an atomic swap.
- `cve_index_updater.py` applies daily deltas from the CVE Program's cvelistV5 for up to 45 days, and downloads the whole index from the latest LOYA release when it is older or missing. Sizes and SHA-256 are checked against GitHub's records.
- `tools/build_cve_index.py` builds the index for a release: it downloads the cvelistV5 baseline (about 670 MB), refuses builds with fewer than 200,000 records, applies the newest delta, marks CISA KEV entries and compresses the result to about 20 MB. Every release must carry it, both inside the zip and as its own asset.
